## 2. Glossary

- **Priorities**:
  - `P0`: Must be resolved before the affected workflow is implemented.
  - `P1`: Substantial functional, security, correctness, or consistency gap.
  - `P2`: Material quality, maintenance, or documentation detail.
- **Audit Classifications**:
  - `BROKEN-SQL` / `BROKEN-API`: Directly invalid SQL DDL or external provider API usage evidenced in current specifications.
  - `CONTRADICTION`: Conflicting states, names, or rules across canonical documents.
  - `MISSING-CONTRACT`: Specification fails to define required schema, concurrency, or recovery behavior.
  - `RISK`: Plausible concrete failure mode arising from the described design.
  - `OPEN-DECISION`: Requires explicit project-owner policy/business decision before finalizing.
  - `DOC-ACCURACY`: Documentation count, path, or explanatory accuracy correction.
- **Lifecycle Statuses**:
  - `NOT_STARTED`, `IN_PROGRESS`, `READY_FOR_REVIEW`, `VERIFIED`, `BLOCKED`.

## 5. Governance Protocols & Completeness Checks

### 5.1 Review, Update & Acceptance-Test Evidence Policy
1. **Before Starting Any Part**: Present the affected findings from this register, obtain explicit owner approval for any `OPEN-DECISION` or `OPEN-POLICY` items in scope, and confirm exact target files (`GOV-05`).
2. **Status Transitions**:
   - `NOT_STARTED` → `IN_PROGRESS`: Scoped work has begun on the assigned Part.
   - `IN_PROGRESS` → `READY_FOR_REVIEW`: Documentation/DDL/contract edits are complete and internally consistent, with diffs presented for owner review.
   - `READY_FOR_REVIEW` → `VERIFIED`: **Requires** dated independent review or executable verification evidence (e.g., Testcontainers Flyway SQL execution, multi-threaded concurrency tests, WireMock payment state-machine tests). Documentation edits alone never qualify as `VERIFIED`.
3. **New Findings Policy**: Any newly discovered issue during Parts 1–12 must be appended to a separate `## 6. Newly Discovered Findings` table using stable IDs (`NEW-001`, `NEW-002`, ...) without altering, merging, or renumbering the original 132 audit IDs.
